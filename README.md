# Anti-scam trainer

Командный MVP-тренажёр безопасного поведения в чатах классифайда. Пользователь выбирает роль покупателя или продавца, изучает распространённые риски, проходит короткие проверки знаний и тренируется на диалоговых сценариях до реального общения на платформе.

## Проблема и решение

Мошеннические сценарии часто выглядят как обычная переписка: просьба перейти по ссылке, сообщить код из SMS, оплатить вне сервиса или продолжить разговор в стороннем мессенджере. Читать правила недостаточно — важно уметь распознавать риск в контексте разговора.

Тренажёр переносит обучение в безопасную симуляцию сделки. Пользователь принимает решения в сценариях, получает разбор последствий и закрепляет навыки через теорию, Quiz, уровни и свободную игру.

## Что реализовано в MVP

- регистрация и вход по логину и паролю, JWT в `HttpOnly` cookie;
- две независимые ролевые ветки: покупатель и продавец;
- 6 Тем в каждой ветке: теория, Quiz и 4 последовательных уровня;
- открытие следующего уровня после результата не ниже одной звезды;
- диалоговые тренировки: готовые сценарии, смешанный ввод и AI-диалог;
- Свободная игра, которая открывается после завершения основных уровней роли;
- Задание дня с объяснением правильного ответа и поддержанием серии дней;
- прогресс, результаты, достижения и рекомендация следующего действия;
- административный API для учебного контента;
- фронтенд-превью всех 11 основных экранов пользовательского пути.

## Структура проекта

```text
anti-scam-trainer/
├── backend/                 # Go API, доменная логика, миграции, OpenAPI и тесты
├── frontend/                # React-приложение
│   └── src/
│       ├── app/             # композиция приложения, роутинг, store, preview-режим
│       ├── entities/        # сущности пользователя, обучения, прогресса
│       ├── features/        # пользовательские действия: вход, выбор роли, старт тренировки
│       ├── widgets/         # составные блоки: Quiz и тренировочный чат
│       ├── pages/           # экраны пользовательского пути
│       └── shared/          # изолированные технические сегменты и UI-примитивы
├── deploy/                  # Docker Compose, Dockerfile и Nginx gateway
├── docs/                    # продуктовая, архитектурная, API- и эксплуатационная документация
├── design-qa.md             # чек-лист сверки интерфейса с дизайном
├── Makefile                 # единые команды запуска и проверки
└── CONTEXT.md               # словарь терминов проекта
```

Фронтенд следует FSD-подобному разделению по ответственности: импорт идёт сверху вниз (`app → pages → widgets → features → entities → shared`), а внешние API скрыты за публичными `index.ts`. Backend реализован как модульный монолит с feature-модулями, разделёнными на transport, service и repository.

## Особенности реализации

- API описан и версионируется через OpenAPI; клиентские контракты изолированы в API-сегментах сущностей.
- RTK Query управляет серверным состоянием, а локальное UI-состояние не смешивается с данными API.
- Контент, попытки и прогресс сохраняются в PostgreSQL через миграции и seed-данные.
- Модель вызывается только сервером. Она получает ограниченный контекст, возвращает строгую JSON-структуру, а при некорректном ответе используется безопасный резервный сценарий.
- Nginx отдаёт frontend и проксирует `/api` в backend под одним origin — так cookie-аутентификация работает корректно и локально, и через туннель.
- Frontend запускается в preview-режиме без backend для демонстрации всех 11 экранов; в интеграционном режиме использует реальные API-контракты.

## Быстрый запуск

### Полный локальный стенд

Нужны Docker Compose, Make, Go и Node.js. В корне репозитория:

```bash
make setup
make build
make up
```

После запуска:

- web gateway: `http://localhost:3000`;
- API: `http://localhost:8080`;
- проверка здоровья API: `http://localhost:8080/api/v1/health`.

Для запуска уровней с локальной моделью:

```bash
make build-ollama
make up-ollama
make ollama-init
```

Перед первым запуском заполните обязательные секреты в `backend/.env`: `JWT_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `SWAGGER_USERNAME`, `SWAGGER_PASSWORD`. Шаблон и подробности — в [инструкции локального запуска](docs/03-operations/local-development.md).

### Frontend в режиме разработки

```bash
cd frontend
npm install
npm run dev
```

Для production-сборки, работающей через gateway:

```bash
cd frontend
VITE_API_BASE_URL=/api npm run build
```
