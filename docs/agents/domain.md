# Доменная документация

Правила для инженерных навыков при исследовании и изменении проекта.

## Что читать до работы

- [Глоссарий домена](../../CONTEXT.md).
- Применимые [ADR](../02-architecture/adr/README.md) из `docs/02-architecture/adr/`.
- Документацию по затронутой области из [индекса docs](../README.md).

Если документация не покрывает необходимый вопрос, продолжайте работу и зафиксируйте реальный пробел только если задача уточняет термин или принимает решение.

## Структура

Это одноконтекстный репозиторий:

```text
/
├── CONTEXT.md

    └── 02-architecture/
        └── adr/
```

## Правила использования

При описании понятий в задачах, коде, тестах и документации используйте термины из `CONTEXT.md`, а не заменяющие их синонимы.

Если планируемое изменение противоречит ADR, укажите это явно. Не меняйте принятое архитектурное решение молча: обновите существующий ADR или добавьте новый.

Обновляйте документацию вместе с кодом, если изменились продуктовые правила, HTTP API, модель данных, архитектура, операции или терминология.
