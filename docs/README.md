# Документация Anti-scam trainer

Документация описывает две разные вещи:

- **текущее состояние** — то, что уже есть в репозитории и может быть проверено по коду;
- **принятое направление** — договорённости команды, которые ещё не обязательно реализованы.

Такое разделение важно для проекта на ранней стадии: план не должен выглядеть как готовая функция, а временный код — как окончательная архитектура.

## Как поддерживать документацию

При изменении поведения нужно обновить документ того же уровня:

- поменялся внешний HTTP-контракт — обновить `08-frontend-api-contracts`;
- поменялся способ запуска — обновить `03-operations`;
- принято решение, которое влияет на несколько компонентов или ограничивает будущую реализацию, — добавить ADR;
- реализована запланированная возможность — перенести её из списка направления в текущее состояние.

Документация не должна скрывать незавершённость проекта. Если функция только обсуждается, это следует написать прямо.

Согласованные предметные термины находятся в корневом [CONTEXT.md](../CONTEXT.md). В коде и документации следует использовать их в том же значении.
