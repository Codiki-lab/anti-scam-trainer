# Текущий HTTP API

Документ описывает маршруты, реализованные в `backend/internal/core/app` на 8 августа 2026 года. Все публичные методы используют версию API `v1`.

## Общие свойства

- Базовый адрес при локальном запуске: `http://localhost:8080`.
- Префикс API: `/api/v1`.
- Авторизация отсутствует.
- Успешные ответы с данными имеют `Content-Type: application/json`.
- Поля дат сериализуются стандартным кодировщиком Go в RFC 3339.
- Ошибки пока возвращаются обычным текстом.
- Каждый ответ содержит `X-Request-ID`. Переданное клиентом значение сохраняется; иначе сервер создаёт идентификатор.
- Старые неверсированные CRUD-маршруты больше не поддерживаются.

## Служебный метод

### `GET /api/v1/health`

Ответ `200 OK`:

```json
{"status":"ok"}
```

Проверка не выполняет запрос к PostgreSQL, поэтому подтверждает только работу HTTP-процесса.

## Пользователи

```json
{
  "id": 1,
  "user_id": "external-42",
  "username": "alex",
  "completed_chats": 0
}
```

`user_id` — внешний идентификатор, `id` — внутренний ключ PostgreSQL.

| Метод | Путь | Поведение |
| --- | --- | --- |
| `GET` | `/api/v1/users` | Список всех пользователей |
| `POST` | `/api/v1/users` | Создание пользователя |
| `GET` | `/api/v1/users/{id}` | Пользователь по внутреннему ID |
| `PUT` | `/api/v1/users/{id}` | Полная запись изменяемых полей пользователя |
| `DELETE` | `/api/v1/users/{id}` | Удаление пользователя, ответ `200 OK` без тела |

Пример создания:

```bash
curl -X POST http://localhost:8080/api/v1/users \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"external-42","username":"alex","completed_chats":0}'
```

## Сценарии

```json
{
  "id": 1,
  "title": "Поддельная доставка",
  "description": "Тренировка безопасного оформления доставки",
  "difficulty": "easy",
  "role": "seller",
  "is_active": true
}
```

`role` — роль пользователя; допустимы `buyer` и `seller`. Поля `difficulty` и физическая таблица `chats` остаются совместимыми техническими деталями текущей схемы.

| Метод | Путь | Поведение |
| --- | --- | --- |
| `GET` | `/api/v1/scenarios` | Список сценариев |
| `POST` | `/api/v1/scenarios` | Создание сценария |
| `GET` | `/api/v1/scenarios/{id}` | Сценарий по ID |
| `PUT` | `/api/v1/scenarios/{id}` | Полная запись изменяемых полей сценария |
| `DELETE` | `/api/v1/scenarios/{id}` | Удаление сценария, ответ `204 No Content` |

## Прохождения

```json
{
  "id": 1,
  "user_id": 1,
  "scenario_id": 1,
  "status": "IN_PROGRESS",
  "started_at": "2026-08-07T18:00:00Z",
  "finished_at": "0001-01-01T00:00:00Z",
  "score": 0
}
```

`user_id` и `scenario_id` — внутренние идентификаторы. В PostgreSQL-адаптере `scenario_id` хранится в историческом столбце `chat_sessions.chat_id`.

| Метод | Путь | Поведение |
| --- | --- | --- |
| `GET` | `/api/v1/attempts` | Список всех прохождений |
| `POST` | `/api/v1/attempts` | Создание прохождения |
| `GET` | `/api/v1/attempts/{id}` | Прохождение по ID |
| `PUT` | `/api/v1/attempts/{id}` | Полная запись изменяемых полей прохождения |
| `DELETE` | `/api/v1/attempts/{id}` | Удаление прохождения, ответ `204 No Content` |

Статус прохождения принимает `IN_PROGRESS`, `COMPLETED` или `ABANDONED`. Разрешены сохранение прежнего статуса и переход из `IN_PROGRESS` в финальный статус; запрещённый переход возвращает `500 Internal Server Error` с текстом `invalid attempt status transition`.

Сервис прохождений также содержит внутренний сценарий завершения: он сохраняет завершённое прохождение и обновлённый прогресс в одной транзакции. Отдельного HTTP-метода завершения пока нет.

## Фактические коды ошибок

| Ситуация | Код |
| --- | --- |
| Неподдерживаемый HTTP-метод | `405 Method Not Allowed` |
| ID в пути отсутствует или не является числом | `400 Bad Request` |
| Некорректный JSON | `400 Bad Request` |
| Ошибка чтения одной записи | `404 Not Found` |
| Остальные ошибки репозитория и недопустимый переход статуса | `500 Internal Server Error` |

Создание и обновление возвращают `200 OK`; код `201 Created` не используется.

## Методы, которых ещё нет

Контракт пока не позволяет клиенту получить шаги и варианты сценария, начать и завершить прохождение отдельными бизнес-командами, отправить ответ или сообщение, получить прогресс и открытые уровни, запустить свободную игру, получить достижения или статистику.
