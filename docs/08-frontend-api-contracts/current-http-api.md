# Текущий HTTP API

Документ описывает маршруты, реализованные в `backend/internal/core/app` на 9 августа 2026 года. Все публичные методы используют версию API `v1`.

## Общие свойства

- Базовый адрес при локальном запуске: `http://localhost:8080`; префикс API: `/api/v1`.
- Ошибки возвращаются обычным текстом; успешные ответы с данными — JSON.
- Каждый ответ содержит `X-Request-ID`.
- `GET /health`, регистрация, вход и выход доступны без аутентификации. Остальные методы требуют валидную cookie `access_token`.
- Cookie содержит подписанный JWT на семь дней, имеет `HttpOnly`, `SameSite=Lax`, `Path=/`; атрибут `Secure` включается для HTTPS-запроса. Токен не передают в теле или заголовке.

## Служебный метод

### `GET /api/v1/health`

Возвращает `200 OK` и `{"status":"ok"}`. PostgreSQL не запрашивается.

## Учётная запись

Публичное представление учётной записи:

```json
{"id":1,"username":"alex","access_role":"user"}
```

`id` — внутренний ключ для связей; не подменяет владельца в методах тренажёра. `username` нормализуется к нижнему регистру, уникален без учёта регистра. Пароль и bcrypt-хеш никогда не возвращаются.

| Метод | Путь | Поведение |
| --- | --- | --- |
| `POST` | `/api/v1/auth/register` | Создаёт учётную запись с ролью `user`, ответ `201 Created` |
| `POST` | `/api/v1/auth/login` | Проверяет логин и пароль, устанавливает cookie, ответ `204 No Content` |
| `POST` | `/api/v1/auth/logout` | Удаляет cookie у текущего клиента, ответ `204 No Content` |
| `GET` | `/api/v1/auth/me` | Возвращает текущую учётную запись из валидной cookie |

Регистрация и вход принимают только:

```json
{"username":"alex","password":"secret"}
```

Оба поля должны быть непустыми. Роль доступа от клиента не принимается. Повторная регистрация логина возвращает `409 Conflict`; неверные учётные данные при входе — `401 Unauthorized` с нейтральным текстом `invalid credentials`.

JWT содержит только `sub` (внутренний ID), `access_role`, `iat` и `exp`. Сервер не хранит сессии, не выпускает refresh token и не отзывает уже выданный JWT: logout удаляет только cookie текущего браузера.

Прежние маршруты `/api/v1/users` и `/api/v1/users/{id}` удалены.

## Сценарии

Все методы сценариев требуют аутентификации.

| Метод | Путь | Поведение |
| --- | --- | --- |
| `GET` | `/api/v1/scenarios` | Список сценариев |
| `POST` | `/api/v1/scenarios` | Создание сценария |
| `GET` | `/api/v1/scenarios/{id}` | Сценарий по ID |
| `PUT` | `/api/v1/scenarios/{id}` | Полная запись сценария |
| `DELETE` | `/api/v1/scenarios/{id}` | Удаление, `204 No Content` |

`role` сценария — роль пользователя в тренировке (`buyer` либо `seller`), а не роль доступа учётной записи.

## Прохождения

Все методы прохождений требуют аутентификации и действуют только над прохождениями текущего пользователя из JWT.

```json
{
  "id": 1,
  "scenario_id": 1,
  "status": "IN_PROGRESS",
  "started_at": "2026-08-07T18:00:00Z",
  "finished_at": "0001-01-01T00:00:00Z",
  "score": 0
}
```

| Метод | Путь | Поведение |
| --- | --- | --- |
| `GET` | `/api/v1/attempts` | Только прохождения текущего пользователя |
| `POST` | `/api/v1/attempts` | Создаёт прохождение текущему пользователю |
| `GET` | `/api/v1/attempts/{id}` | Только собственное прохождение |
| `PUT` | `/api/v1/attempts/{id}` | Изменяет только собственное прохождение |
| `DELETE` | `/api/v1/attempts/{id}` | Удаляет только собственное прохождение |

`user_id` в теле не принимается и в ответе не возвращается. Чужое или отсутствующее прохождение возвращает `404 Not Found`, а отсутствующая, невалидная или истёкшая cookie — `401 Unauthorized` до выполнения бизнес-операции.

## Фактические коды ошибок

| Ситуация | Код |
| --- | --- |
| Отсутствующий, невалидный или истёкший JWT | `401 Unauthorized` |
| Занятый логин | `409 Conflict` |
| Пустой логин или пароль, некорректный JSON, неверный ID | `400 Bad Request` |
| Несуществующее или чужое прохождение | `404 Not Found` |
| Неподдерживаемый метод | `405 Method Not Allowed` |
