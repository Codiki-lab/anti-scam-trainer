# Текущий HTTP API

Документ описывает только маршруты, собранные через `backend/internal/app_builder` из HTTP-модулей на 8 августа 2026 года. Это ещё не целевой API тренажёра.

## Общие свойства

- Базовый адрес при локальном запуске: `http://localhost:8080`.
- Версия API в пути отсутствует.
- Авторизация отсутствует.
- Успешные ответы с данными имеют `Content-Type: application/json`.
- Поля дат сериализуются стандартным кодировщиком Go в RFC 3339.
- Единого JSON-формата ошибок пока нет: сервер возвращает обычный текст.
- Каждый ответ содержит `X-Request-ID`. Если клиент передал этот заголовок в запросе, сервер сохраняет его значение; иначе создаёт новый идентификатор.

## Служебные методы

### `GET /`

Возвращает текст:

```text
AntiScamTrainer backend is running
```

### `GET /health`

Ответ `200 OK`:

```json
{"status":"ok"}
```

Проверка не выполняет запрос к PostgreSQL, поэтому подтверждает только работу HTTP-процесса.

## Пользователи

### Модель

```json
{
  "id": 1,
  "user_id": "external-42",
  "username": "alex",
  "completed_chats": 0
}
```

`user_id` — внешний идентификатор, `id` — внутренний ключ PostgreSQL.

| Метод | Путь | Поведение |
| --- | --- | --- |
| `GET` | `/users` | Список всех пользователей |
| `POST` | `/users` | Создание пользователя |
| `GET` | `/users/{id}` | Пользователь по внутреннему ID |
| `PUT` | `/users/{id}` | Полная запись изменяемых полей пользователя |
| `DELETE` | `/users/{id}` | Удаление пользователя, ответ `200 OK` без тела |

Пример создания:

```bash
curl -X POST http://localhost:8080/users \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"external-42","username":"alex","completed_chats":0}'
```

## Сценарии

### Модель

```json
{
  "id": 1,
  "title": "Поддельная доставка",
  "description": "Тренировка безопасного оформления доставки",
  "difficulty": "easy",
  "role": "seller",
  "is_active": true
}
```

В текущей модели `role` означает роль пользователя, но имя поля пока не устраняет двусмысленность. Допустимы только значения `buyer` и `seller`; другое значение приводит к ошибке PostgreSQL, которую текущий обработчик возвращает как `500 Internal Server Error`.

| Метод | Путь | Поведение |
| --- | --- | --- |
| `GET` | `/chats` | Список сценариев |
| `POST` | `/chats` | Создание сценария |
| `GET` | `/chats/{id}` | Сценарий по ID |
| `PUT` | `/chats/{id}` | Полная запись изменяемых полей сценария |
| `DELETE` | `/chats/{id}` | Удаление сценария, ответ `204 No Content` |

## Прохождения

### Модель

```json
{
  "id": 1,
  "user_id": 1,
  "chat_id": 1,
  "status": "IN_PROGRESS",
  "started_at": "2026-08-07T18:00:00Z",
  "finished_at": "0001-01-01T00:00:00Z",
  "score": 0
}
```

`user_id` здесь является внутренним ID из таблицы `users`. `finished_at` в Go-модели не является nullable, поэтому незавершённая сессия может возвращать нулевую дату.

`status` принимает `IN_PROGRESS`, `COMPLETED` или `ABANDONED`. Через текущий CRUD разрешены только сохранение прежнего статуса и переход `IN_PROGRESS` в один из финальных статусов; нарушение возвращается как `500 Internal Server Error`, пока общий формат прикладных ошибок не введён.

| Метод | Путь | Поведение |
| --- | --- | --- |
| `GET` | `/chat-sessions` | Список всех прохождений всех пользователей |
| `POST` | `/chat-sessions` | Создание прохождения |
| `GET` | `/chat-sessions/{id}` | Прохождение по ID |
| `PUT` | `/chat-sessions/{id}` | Полная запись изменяемых полей прохождения |
| `DELETE` | `/chat-sessions/{id}` | Удаление прохождения, ответ `204 No Content` |

## Фактические коды ошибок

| Ситуация | Код |
| --- | --- |
| Неподдерживаемый HTTP-метод | `405 Method Not Allowed` |
| ID в пути не является числом | `400 Bad Request` |
| Некорректный JSON | `400 Bad Request` |
| Ошибка чтения одной записи | `404 Not Found` |
| Остальные ошибки репозитория | `500 Internal Server Error` |

Создание и обновление сейчас возвращают `200 OK`; код `201 Created` не используется.

## Методы, которых ещё нет

Контракт пока не позволяет клиенту:

- получить шаги и варианты сценария;
- начать сессию отдельной бизнес-командой;
- отправить ответ или сообщение;
- получить следующую AI-реплику;
- завершить прохождение и получить разбор;
- получить раздельный прогресс покупателя и продавца;
- получить звёзды и вычисленное состояние `is_locked`;
- запустить свободную игру;
- получить достижения или статистику.

Эти методы следует проектировать вместе с игровым циклом, а не выводить из текущего CRUD автоматически.
