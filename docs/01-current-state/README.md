# Текущее состояние

На 7 августа 2026 года репозиторий содержит каркас бэкенда и локальной инфраструктуры. Основной пользовательский сценарий тренажёра ещё не собран целиком.

Согласованное, но ещё не реализованное поведение описано отдельно в документах [«Продукт и границы MVP»](product.md) и [«Игровая прогрессия»](game-design.md).

## Что уже есть

| Область | Состояние |
| --- | --- |
| HTTP-сервер | Работает на стандартном `net/http`, порт задаётся через `PORT`; в Compose запускается после миграций |
| Пользователи | CRUD для `users` |
| Сценарии | CRUD для `chats`; схема также подготовлена для уровней и шагов |
| Прохождения | CRUD для `chat_sessions`; схема поддерживает свободную игру и ответы шагов, но HTTP-методов для них пока нет |
| PostgreSQL | Описан в Docker Compose; versioned-миграция создаёт начальную SQL-схему |
| Ollama | Описан отдельным Compose-файлом, модель загружается по `OLLAMA_MODEL` |
| Проверка состояния | `GET /health` возвращает `{"status":"ok"}` |

Бэкенд организован продуктовыми модулями `users`, `chats`, `sessions` и `progress`. Внутри реализованных HTTP-возможностей HTTP-слой, сервис и PostgreSQL-репозиторий разделены физически; общие предметные модели и чистые правила находятся в `backend/internal/core/domain`. Создание соединения с БД и связывание зависимостей собрано в `app_builder`.

## Чего пока нет

- фронтенд-приложения;
- HTTP-методов для шагов сценария, вариантов ответа и сообщений;
- игрового цикла «начать сценарий → ответить → получить следующую реплику → завершить»;
- AI-провайдера и обращения к Ollama из Go-кода;
- проверки и оценки свободного ответа;
- авторизации и привязки запроса к текущему пользователю;
- готовых Docker-образов бэкенда и фронтенда;
- настроенного Nginx.

## Известные технические ограничения

1. При локальном `go run .` бэкенд ожидает переменные `POSTGRES_NAME`, `POSTGRES_HOST` и `POSTGRES_PORT`, а пример окружения содержит только `POSTGRES_DB`. Docker Compose передаёт необходимые значения автоматически.
2. Начальная схема находится в обратимой versioned-миграции `000001_initial_schema`. Контейнер миграций применяет её и все последующие миграции перед запуском API в Compose.
3. В SQL-схеме есть сущности, для которых ещё нет моделей и репозиториев: шаги, варианты ответа, сообщения, достижения, статистика и рейтинг.
4. `make lint` и `make test` всегда вызывают команды фронтенда, хотя `frontend/package.json` пока отсутствует.

Эти пункты описывают фактическое состояние, а не утверждённый план исправлений.

## Проверенный минимум

Команда ниже запускает тесты доменных правил и HTTP-контракта без PostgreSQL:

```bash
cd backend
go test ./...
```

Тесты домена проверяют допустимые переходы статуса прохождения и границы звёзд. HTTP-тесты собирают роутер с тестовыми реализациями репозиториев и проверяют наблюдаемое поведение существующего CRUD.
