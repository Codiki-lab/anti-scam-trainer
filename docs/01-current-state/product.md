# Продукт и границы MVP

## Зачем нужен тренажёр

Anti-scam trainer даёт безопасное место для тренировки перед реальным общением на сервисе объявлений. Пользователь участвует в диалоге как покупатель или продавец, замечает признаки риска и выбирает безопасные действия.

Это не справочник с перечнем мошеннических схем и не викторина вне контекста. Основная ценность продукта — решение внутри правдоподобного разговора и понятный разбор последствий.

## Что команда решила

- Развивать монолитный MVP, не выделяя микросервисы заранее.
- Основой тренировки сделать чатовый сценарий.
- Разделить обучение на независимые ролевые ветки покупателя и продавца.
- В каждой ролевой ветке иметь шесть Тем; каждая содержит Теорию, Quiz и четыре последовательных Уровня.
- Открывать следующий уровень после прохождения предыдущего хотя бы на одну звезду.
- Хранить лучший результат уровня от одной до трёх звёзд; три звезды не нужны для открытия основного контента.
- Открывать Свободную игру для Ролевой ветки после прохождения Уровня 4 хотя бы на одну Звезду во всех шести её Темах.
- Использовать готовые сценарии на первых двух уровнях, смешанный ввод с участием модели на третьем и свободный AI-диалог на четвёртом.
- На четвёртом уровне виртуальный собеседник всегда является мошенником. Только в свободной игре он может оказаться мошенником или обычным участником сделки.
- Добавить Ежедневное задание как короткую учебную активность для возвращения Пользователя и поддержания Серии дней. Оно засчитывается после одного окончательного ответа Пользователя, независимо от правильности, и сразу показывает правильный ответ с кратким разбором: вердикт, до трёх признаков риска или безопасности в Снимке диалога и безопасное действие. После выполнения Dashboard показывает сохранённый разбор и статус выполнения, но не позволяет ответить повторно. Любая другая учебная активность также поддерживает Серию дней. При первом открытии Dashboard в календарный день `Europe/Moscow` сервер создаёт и закрепляет за Пользователем один Снимок диалога. Ролевая ветка задания выбирается случайно. AI генерирует снимок и разметку с учётом Учебного профиля; сервер сохраняет их для повторной выдачи. При недоступности или некорректном ответе AI используется курируемый резервный снимок.
- Принять целевую модель со сценариями, шагами, вариантами ответа, прохождениями и отдельными ответами пользователя.
- Для MVP идентифицировать пользователя локальной учётной записью с уникальным логином и паролем, чтобы его прогресс был доступен после повторного входа.
- Регистрация требует непустые логин и пароль и `training_role=buyer|seller`; правила длины и состава пароля для MVP не вводятся.
- Использовать `username` как единственный публичный логин пользователя; устаревший внешний идентификатор `user_id` удалить из целевой модели и API.
- Не поддерживать восстановление и сброс пароля в MVP.
- После успешного входа сохранять самодостаточный подписанный JWT access token на семь дней в `HttpOnly` cookie; refresh token и серверное хранилище сессий в MVP не использовать.
- Выход из учётной записи очищает auth-cookie только в текущем браузере и не отзывает уже выданный token.
- Внешний API учётной записи состоит из регистрации, входа, выхода и получения текущего пользователя; открытый CRUD пользователей не входит в MVP.
- Все пользовательские методы тренажёра, кроме регистрации и входа, доступны только после аутентификации и используют идентичность из access token, а не из параметров клиента.
- Учётная запись имеет роль доступа: `user` работает с тренажёром, `admin` управляет учебным контентом через защищённый HTTP API и web-админку. Интерфейс полностью покрывает Темы, Теорию и Quiz, а для Сценариев — основные поля и lifecycle, доступные для чтения текущим контрактом.
- Публичная регистрация всегда создаёт `user`. Единственный `admin` MVP создаётся при запуске из конфигурации и не назначается через API.

Подробные правила находятся в [описании игровой прогрессии](game-design.md), а согласованные названия — в [словаре проекта](../../CONTEXT.md).

## Минимальный сквозной сценарий

Следующий поток задаёт реализованную границу MVP:

1. Пользователь создаёт учётную запись или входит с логином и паролем.
2. Пользователь выбирает роль покупателя или продавца.
3. Dashboard показывает Темы, серверное `continue_action` и устойчивое Задание дня для выбранной ролевой ветки.
4. Пользователь читает Теорию, проходит Quiz минимум на 80% и запускает Сценарий открытого Уровня.
5. Система создаёт прохождение и последовательно обрабатывает ответы.
6. После завершения система атомарно сохраняет Result, Прогресс, Серию дней и новые Достижения.
7. Если получена хотя бы одна звезда, следующий уровень этой ролевой ветки становится доступен.

До начала и после завершения Темы Пользователь может пройти необязательную Проверку навыка. После Прохождений система формирует агрегированный Профиль ошибок, а Result может предложить микро-вопрос и персональную рекомендацию, не обходящую основную последовательность.

Поток охватывает Уровни 1–4 обеих ролевых веток и отдельную Свободную игру. Учебный контент создаёт и изменяет администратор через API; количество управляемых шагов не задано кодом.

Задание дня хранится отдельно для покупателя и продавца в пределах календарного дня `Europe/Moscow`. Приоритет рекомендации: восстановить незавершённое Прохождение, прочитать следующую Теорию, пройти следующий Quiz, завершить открытый Уровень, затем играть в Свободную игру. Выполнение фиксируется только соответствующим учебным действием, а не отдельной командой клиента.

Темы используют lifecycle `draft`, `published`, `archived`. Администратор изменяет только черновик; публикация требует пять блоков Теории, пять вопросов Quiz по четыре варианта с одним правильным и опубликованные Сценарии Уровней 1–4. Архивация не удаляет исторические Прогресс, попытки Quiz, Прохождения или Results.

## Реализация AI и демонстрации

Демо-макет чата Avito после явного согласия Пользователя передаёт в `learning` только обезличенный Снимок диалога и нормализованный риск. Сервис выбирает опубликованную Тему той же Ролевой ветки и возвращает безопасное объяснение и разрешённое следующее действие, не сохраняя снимок и не раскрывая внутренние данные AI. Для неподдержанной или неточной пары риск–роль он возвращает явно помеченную общую рекомендацию сервера.

Рубрики и инструкции принадлежат данным Сценария. На Уровне 3 qwen3:8b работает только как Evaluator; на Уровне 4 и в Свободной игре отдельные Evaluator и Generator возвращают строгие JSON-контракты. Обратная связь показывается в итоговом разборе. Nginx отдаёт веб-сборку и проксирует `/api` под одним origin, который можно туннелировать через ngrok.
