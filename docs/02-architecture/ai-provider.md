# Технический AI provider

`backend/internal/core/aiprovider` скрывает HTTP-протокол Ollama от сервиса Прохождений. Техническая граница принимает обычный либо structured-запрос, а локальный адаптер продуктовой возможности предоставляет модель порту `Evaluator`. `ScammerGenerator` остаётся отдельным локальным портом возможности, но детерминированно выбирает серверную реплику и не вызывает технический provider. Промпты и правила Сценария не входят в технический provider.

Composition root создаёт provider из конфигурации. Сервис не читает `OLLAMA_*` и не создаёт собственный HTTP-клиент.

## Контракт и ошибки

Один вызов provider выполняет один непотоковый запрос к `POST /api/chat`. Игровой evaluator передаёт JSON schema, `think:false`, `num_predict=120` и `temperature=0`. Шкала evaluator-а явно задана как `1` — опасный, `2` — неоднозначный, `3` — в основном безопасный и `4` — безопасный Ответ; `is_safe=true` принимается только вместе с `score=3..4`.

До вызова модели evaluator локально распознаёт короткий недвусмысленный отказ с названным опасным действием: например, «не открою ссылку», «не дам код» или «не буду платить». Такой Ответ пользователя сразу получает `score=4`, только если названное действие соответствует текущему `risk_type`. Другие соответствующие текущему риску явные безопасные действия получают консервативный `score=3`, а безусловное согласие или соответствующее риску названное опасное действие — `score=1`. Локальная проверка отличает отрицание действия от согласия; смешанный ответ с последующим согласием не проходит быстрый безопасный путь. Голый отказ без объекта, безопасная или опасная фраза о другом риске и ответы обычному участнику сделки в Свободной игре оцениваются моделью по смыслу. Для локально распознанного опасного действия `detected_signals` формируется сервером из авторитетного `risk_type` Сценария. Валидированные сигналы модели не подменяются, а неоднозначному Ответу fallback не приписывает отсутствующий сигнал.

Локальная реализация evaluator-а выполняет не более одной repair-попытки после успешного, но невалидного structured-ответа. Транспортная ошибка, отмена или исчерпание контекста возвращаются сразу: Прохождение не меняется, а Пользователь может повторить запрос. Повторно невалидная оценка заменяется детерминированной консервативной fallback-оценкой по тексту Ответа пользователя. Generator сначала использует безопасную ещё не показанную fallback-реплику текущего Шага, затем — ещё не показанную курируемую Вариацию тактики текущей фазы.

Единственный локальный provider допускает не более одного AI-запроса одновременно для всех Пользователей. Очередь имеет фиксированную ёмкость `0`: конкурентный запрос не накапливается в памяти, получает `429 RATE_LIMITED` и может быть повторён клиентом после `Retry-After`. Пользовательские квоты при этом считаются отдельно по `user_id`.

После успешного ответа результат содержит:

- текст реплики виртуального собеседника;
- фактические `prompt_eval_count` и `eval_count`, сообщённые Ollama;
- оценку prompt до вызова, резерв вывода, размер окна, расчётную долю занятого окна и `low` / `medium` / `high` риск.

Ошибки различаются типами: `TransportError` для сети и таймаута, `OllamaError` для неуспешного HTTP-ответа Ollama, `MalformedResponseError` для неполного или неверного успешного ответа и `ContextCapacityError` для истории, не помещающейся с резервом. Отмена контекста вызывающего кода возвращается как `context.Canceled` или его исходная ошибка, без оборачивания в транспортную ошибку.

## Бюджет контекста

Размер окна, резерв и пороги задаются конфигурацией. Если резерв не указан (`0`), он равен большему из 20% окна и 256 токенов. Риск считается от `(оценка prompt + резерв) / размер окна`:

- `low` — менее 60%;
- `medium` — от 60% до 75%;
- `high` — от 75% до предельной вместимости.

При `оценка prompt + лимит вывода > 75% размера окна` structured-запрос не уходит в Ollama. Это оставляет технический запас и не является способом обнаружить галлюцинацию.

## Policy и история

Версионируемые полные источники buyer/seller-Теории и компактные policy находятся в `backend/internal/features/attempts/service/content`; runtime-policy встраивается из одного JSON-источника. Runtime выбирает только одну Ролевую ветку и основной тип риска. Evaluator получает текущий Ответ пользователя как отдельное недоверенное JSON-поле, контекст конкретного Шага и не более двух предыдущих Сообщений. Для обычного участника Свободной игры используется отдельная policy. Детерминированный Generator получает явные роли сторон, текущую фазу, разрешённые тактики и не более трёх последних пар реплик, чтобы не повторять уже показанный контент. После четвёртой пары сервер сохраняет compact summary. Полные источники Теории, соседние Сценарии и внутренний AI-контекст в публичные DTO не попадают.

Backend хранит bounded-окно последних 1024 задержек отдельно для evaluator-а и детерминированного generator-а. Аутентифицированный `GET /api/v1/ai/metrics` возвращает только агрегаты `calls`, `errors`, `retries`, `fallbacks` и `p95_latency_ms`, без Ответов пользователя, prompt, policy или rubric.

## Preflight-оценка

Текущая локальная конфигурация использует `qwen3:8b`. До вызова применяется консервативная оценка: UTF-8 байты ролей и текста плюс служебный запас на формат чата. Поэтому она намеренно может быть больше итогового `prompt_eval_count`, в том числе для русскоязычных реплик. Для выбранной модели принята проверяемая погрешность: оценка не должна быть меньше фактического `prompt_eval_count` и не должна превышать большее из 32 токенов и 100% фактического значения на контрольных английской и русскоязычной историях. Токенизация и шаблон чата зависят от версии модели и Ollama, поэтому эта оценка не заявляет модель-независимую точность.

После успешного вызова `prompt_eval_count` Ollama остаётся авторитетным наблюдением для калибровки оценки, а `eval_count` — фактическим размером сгенерированного ответа. `OLLAMA_PREFLIGHT_TEST=1 go test ./internal/tests/aiprovider -run Qwen3Preflight` выполняет калибровку с реальным локальным Ollama и `qwen3:8b`; по умолчанию этот тест пропускается, поэтому обычная проверка не требует модели, Docker или сети. При смене модели следует выполнить эту калибровку на репрезентативных, включая русскоязычные, историях и при необходимости заменить estimator вместе с тестами; до этого сохраняется консервативная защита от переполнения, но не точный подсчёт.

## Конфигурация

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `OLLAMA_URL` | `http://localhost:11434` | Адрес Ollama |
| `OLLAMA_MODEL` | `qwen3:8b` | Локальная модель |
| `OLLAMA_REQUEST_TIMEOUT` | `30s` | Таймаут одного вызова |
| `OLLAMA_CONTEXT_WINDOW_TOKENS` | `8192` | Реально используемый размер окна |
| `OLLAMA_OUTPUT_RESERVE_TOKENS` | `0` | Резерв; `0` включает правило 20% / 256 |
| `OLLAMA_MEDIUM_RISK_THRESHOLD` | `0.60` | Граница `low` → `medium` |
| `OLLAMA_HIGH_RISK_THRESHOLD` | `0.75` | Граница `medium` → `high` |

В Compose адрес backend заменяется на имя контейнера Ollama. Настройка provider не делает сетевого запроса на старте, поэтому обычный запуск без Ollama сохраняется.
