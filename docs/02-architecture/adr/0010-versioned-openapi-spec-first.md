# ADR-0010: Версионированные OpenAPI-спецификации как API-контракт

- Статус: принято
- Дата: 2026-08-09

## Контекст

Текущий HTTP API доступен по версионному префиксу `/api/v1`, а ADR-0006 предусматривает параллельное существование несовместимых версий. Для интерактивной документации требуются точный контракт и переключение между версиями. Рассматривались генерация Swagger-описания из Go-аннотаций и явная спецификация OpenAPI.

## Решение

Контракт каждой версии API ведётся вручную в OpenAPI 3.1 YAML-файле `backend/openapi/vN/openapi.yaml`. Для текущей версии источником контракта является `backend/openapi/v1/openapi.yaml`; приложение отдаёт его по `/openapi/v1.yaml`. Swagger UI открывается по `/swagger/` и содержит переключатель доступных спецификаций, начиная с единственной `v1`. При появлении новой версии ей соответствует отдельный файл и отдельный URL спецификации.

Маршруты Swagger UI и OpenAPI-спецификаций защищаются отдельным middleware HTTP Basic Auth. Логин и пароль документации передаются обязательными переменными окружения `SWAGGER_USERNAME` и `SWAGGER_PASSWORD`; они не попадают в спецификацию, исходный код или репозиторий.

Go-аннотации и генераторы спецификаций не используются как источник истины. Изменение внешнего HTTP-контракта требует синхронного обновления соответствующей OpenAPI-спецификации и проверки её согласованности с маршрутом.

## Последствия

- API-контракт остаётся независимым от реализации и читаемым для фронтенда.
- Версии не смешиваются в одном документе и могут сосуществовать в Swagger UI.
- Доступ к документации требует отдельной учётной информации и не зависит от JWT пользователя тренажёра.
- Команда должна поддерживать спецификацию вручную и проверять её вместе с HTTP-методами.
