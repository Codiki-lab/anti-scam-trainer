# ADR-0014: раздельные AI-порты evaluator и generator

- Статус: принято
- Дата: 2026-08-10
- Пересмотрено: 2026-08-14
- Уточняет: ADR-0002, ADR-0003, ADR-0008

## Контекст

Один AI-результат одновременно оценивал Ответ пользователя, начислял сырые очки и создавал реплику виртуального собеседника. Такая граница позволяла модели влиять на ход Прохождения и передавала ей лишний контекст даже там, где реплика уже подготовлена в Сценарии.

## Решение

Продуктовая возможность `attempts` определяет два локальных порта. `Evaluator` принимает установленную сервером policy, тип риска, управляемую инструкцию и rubric Сценария, контекст конкретного Шага, текущий Ответ пользователя и минимальную историю; возвращает только оценку 1–4, безопасность, тип риска, до трёх сигналов, объяснение и безопасное действие. `ScammerGenerator` является детерминированным серверным селектором: сначала использует безопасную ещё не показанную fallback-реплику текущего Шага, затем — ещё не показанную Вариацию тактики разрешённой сервером фазы. Модель не участвует в выборе реплики.

Сервер отображает оценку в 0/25/75/100, управляет фазами, переходами, пределом пяти Ответов пользователя, завершением, Result и Прогрессом. Уровни 1–2 AI не вызывают; L3, L4 и Свободная игра вызывают модель только через evaluator. После двух Ответов L4 и Свободную игру можно завершить досрочно, после пятого Ответа сервер завершает Прохождение автоматически.

Ollama получает JSON schema evaluator-а с `thinking:false`. Шкала фиксирована: `1` — опасный, `2` — неоднозначный, `3` — в основном безопасный, `4` — безопасный Ответ; `is_safe=true` допустим только для `score=3..4`. Явные безопасные и рискованные действия оцениваются локально; для локально распознанного опасного действия сигнал нормализуется из авторитетного `risk_type` Сценария, а валидированные сигналы результата модели сохраняются без подмены. Результат модели проходит строгую schema/policy-валидацию; допускается одна repair-попытка только после успешного, но невалидного structured-ответа. Транспортная ошибка не повторяется внутри одного HTTP-запроса. Повторно невалидный evaluator использует детерминированную консервативную fallback-оценку и не приписывает неоднозначному Ответу отсутствующий сигнал.

## Последствия

- Модель не может начислить Баллы, сменить фазу или завершить Прохождение.
- Все реплики Виртуального собеседника воспроизводимы и не требуют второго model inference.
- Полная Теория остаётся версионируемым источником. Runtime получает policy выбранной Ролевой ветки и риска, а также только управляемые поля опубликованного Сценария, нужные соответствующему AI-порту.
- Публичные GameState и Result не раскрывают policy, rubric, контекст evaluator-а, фазу и compact summary.
- Изменение структуры evaluator-результата требует отдельной schema, валидации и портового теста.
