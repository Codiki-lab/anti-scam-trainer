# ADR-0009: подписанный JWT access token в cookie

- Статус: принято
- Дата: 2026-08-08

## Контекст

Пользователю нужен повторный вход для доступа к своему прогрессу, но MVP должен оставаться простым для демонстрации. Рассматривались серверные сессии с их хранением в PostgreSQL и самодостаточный подписанный JWT access token.

## Решение

После успешной аутентификации сервер выдаёт самодостаточный подписанный JWT access token сроком на семь дней через cookie `access_token`. Cookie имеет `HttpOnly`, `SameSite=Lax`, `Path=/`; `Secure` включается для HTTPS-запроса. JWT подписывается обязательной переменной окружения `JWT_SECRET`; без неё API не запускается. Сервер не хранит сессии, не использует refresh token и не поддерживает отзыв отдельного токена до его истечения.

JWT содержит только внутренний идентификатор пользователя в `sub`, роль доступа в `access_role`, а также стандартные временные claims `iat` и `exp`. В него не включаются логин, пароль и данные обучения.

Выход из учётной записи реализуется удалением cookie у текущего клиента.

## Последствия

- Фронтенд не хранит и не читает token, а браузер передаёт его автоматически.
- Проверка аутентификации не требует чтения таблицы сессий.
- Выход из приложения может лишь удалить cookie у текущего клиента; скомпрометированный token остаётся действителен до семи дней.
- Для отзыва сессий, смены пароля с немедленной инвалидизацией или многоустройственного управления входами понадобится новое решение.
