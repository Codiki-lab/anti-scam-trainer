# ADR-0006: core/server и версионированные HTTP-маршруты

- Статус: принято
- Дата: 2026-08-08
- Заменяет часть ADR-0005 о размещении `app_builder` вне трёх контейнеров `internal`

## Контекст

HTTP-инфраструктура сейчас разделена между `internal/app_builder`, `core/transport/httpserver` и `core/transport/httputil`. Название `httputil` не показывает назначение кода, а роутер в техническом пакете напрямую импортирует продуктовые возможности. Текущий HTTP-контракт не имеет версии в пути.

## Решение

В `backend/internal` остаются только контейнеры `core`, `features` и `tests`.

`app_builder` переносится в `core/app` и остаётся composition root: он создаёт инфраструктурные адаптеры, связывает их с продуктовыми модулями и собирает маршруты. Это единственное место в `core`, которому разрешено зависеть от конкретных продуктовых возможностей.

Общий HTTP-код размещается в `core/server`. В корне пакета остаётся только конфигурация HTTP-сервера. Остальные обязанности разделены на подпакеты:

- `runtime` запускает и штатно останавливает `http.Server`;
- `router` определяет маршрут, версию API и версионный роутер;
- `middleware` содержит общую цепочку middleware;
- `request` декодирует и валидирует HTTP-запросы;
- `response` формирует HTTP-ответы и отслеживает код ответа.

Каждый HTTP-адаптер продуктовой возможности возвращает набор маршрутов. `core/app` регистрирует их в роутере версии `v1`, доступной по префиксу `/api/v1`. Общий сервер и версионный роутер не импортируют продуктовые возможности.

## Последствия

- HTTP-маршруты получают явную точку развития: новая несовместимая версия добавляется рядом с существующей.
- Технический HTTP-код не зависит от пользователей, сценариев или прохождений.
- Сборка приложения остаётся видимой в одном месте, но не нарушает ограничение трёх контейнеров `internal`.
- Текущие неверсированные маршруты заменяются маршрутами `/api/v1`; это меняет внешний HTTP-контракт и требует обновить его документацию и тесты при реализации.
