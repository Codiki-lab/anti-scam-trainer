# ADR-0015: один локальный AI-provider с деградацией для MVP

- Статус: принято
- Дата: 2026-08-13
- Пересмотрено: 2026-08-14
- Уточняет: ADR-0002, ADR-0014

## Контекст

Две копии `qwen3:8b` на одном MacBook Pro с 24 ГБ объединённой памяти не создают независимого резерва: они конкурируют за память с приложением и разделяют отказ оборудования, Ollama и питания. Для MVP важнее предсказуемо сохранить Прохождение, чем заявлять недоказуемую доступность 99%.

## Решение

MVP использует один заранее прогретый локальный AI-provider только для evaluator-а. Backend ограничивает параллелизм и очередь AI-запросов. Одна repair-попытка выполняется лишь после успешного, но невалидного structured-ответа; транспортная ошибка и исчерпание контекста не повторяются внутри того же HTTP-запроса. При такой ошибке Шаг и Ответ не сохраняются, и Пользователь может повторить запрос. Реплику Виртуального собеседника сервер выбирает детерминированно из контента Сценария и Вариаций тактики. Внешний резервный provider с тем же structured-контрактом — отдельный production-шаг и должен размещаться вне локальной машины.

## Последствия

- Локальное демо не требует второй копии модели и не усугубляет свопинг памяти.
- Прохождение не теряет и не дублирует состояние при сбое AI.
- Утверждение о 99% доступности допустимо только после отдельного резерва и измерений SLO.
