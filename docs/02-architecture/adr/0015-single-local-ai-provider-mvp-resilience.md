# ADR-0015: один локальный AI-provider с деградацией для MVP

- Статус: принято
- Дата: 2026-08-13
- Уточняет: ADR-0002, ADR-0014

## Контекст

Две копии `qwen3:8b` на одном MacBook Pro с 24 ГБ объединённой памяти не создают независимого резерва: они конкурируют за память с приложением и разделяют отказ оборудования, Ollama и питания. Для MVP важнее предсказуемо сохранить Прохождение, чем заявлять недоказуемую доступность 99%.

## Решение

MVP использует один заранее прогретый локальный AI-provider. Backend ограничивает параллелизм и очередь AI-запросов, применяет ограниченное число повторов только к идемпотентному вызову без записи состояния и наблюдает ошибки, задержку и переходы на деградацию. При проблеме генератора сервер использует разрешённую ещё не показанную fallback-реплику; при транспортной ошибке evaluator-а Шаг и Ответ не сохраняются и Пользователь может повторить запрос. Внешний резервный provider с тем же structured-контрактом — отдельный production-шаг и должен размещаться вне локальной машины.

## Последствия

- Локальное демо не требует второй копии модели и не усугубляет свопинг памяти.
- Прохождение не теряет и не дублирует состояние при сбое AI.
- Утверждение о 99% доступности допустимо только после отдельного резерва и измерений SLO.
