# ADR-0002: локальная генеративная модель через Ollama

- Статус: принято
- Дата: 2026-08-07

## Контекст

Основная механика тренажёра строится вокруг диалога, в котором виртуальный собеседник должен вести себя естественно и не раскрывать учебную схему одной шаблонной репликой. Команда решила использовать генеративную модель и подготовила локальный запуск Ollama.

На момент решения конкретная модель ещё меняется: в обсуждении упоминалась Qwen, а в текущем примере окружения указана `qwen3:8b`.

## Решение

Использовать Ollama как локальную среду запуска модели. Имя модели передавать через `OLLAMA_MODEL`, а адрес — через `OLLAMA_URL`.

В бэкенде обращение к модели должно находиться за отдельным AI-провайдером. Бизнес-логика диалога не должна зависеть от HTTP-формата Ollama или от имени конкретной модели.

## Последствия

- Для базовой демонстрации не нужен внешний AI-сервис и его ключи.
- Сценарий можно запускать в контролируемом локальном окружении.
- Качество и скорость ответа зависят от выбранной модели и доступного оборудования.
- Образ модели занимает дополнительное место и требует предварительной загрузки.
- Смена модели не должна требовать изменений в сервисном слое.

## Текущее состояние реализации

Compose-файл и команда загрузки qwen3:8b уже есть. `internal/aiprovider` реализует непотоковый диалоговый вызов Ollama, usage и контроль бюджета контекста; composition root передаёт его сервису Прохождений через локальный адаптер. Сервис строго проверяет предметный JSON до любой записи.

## Не входит в решение

ADR не фиксирует конкретную модель, системный промпт, правила оценки ответа или поведение при недоступности Ollama.
