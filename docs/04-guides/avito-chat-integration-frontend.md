# Frontend handoff: демо-интеграция с чатом Avito

> Статус: backend-контракт реализован для демонстрации; не является контрактом реального API Avito.
>
> Канонический контракт: OpenAPI v1, `POST /api/v1/integrations/avito-chat/recommendations`. Этот документ фиксирует пользовательский путь и границу между макетом чата Avito и тренажёром.

## Цель демо

Показать, что Anti-scam trainer может быть частью пользовательского сценария Avito, а не отдельным сайтом. В макете чата Avito сервисная AI-модерация замечает риск в переписке, показывает предупреждение прямо в чате и предлагает разобрать ситуацию в тренажёре. После явного действия Пользователя тренажёр получает обезличенный Снимок диалога, определяет подходящую Тему и открывает релевантную практику.

Макет не должен утверждать, что фронтенд подключён к настоящим системам Avito или что тренажёр читает реальные чаты без согласия Пользователя.

## Сквозной пользовательский путь

```text
Макет чата Avito
  → новое подозрительное Сообщение
  → сервисная реплика AI-модерации Avito
  → Пользователь нажимает «Разобрать ситуацию»
  → экран согласия на передачу обезличенного Снимка диалога
  → integration API тренажёра подбирает Тему и Уровень
  → экран рекомендации с объяснением
  → Теория или Уровень выбранной Темы
```

Главный демонстрационный случай — фишинговая ссылка в переписке о покупке. Для Ролевой ветки `buyer` она должна приводить к Теме `buyer-phishing-links` («Фишинговые ссылки»); для `seller` — к `seller-external-links` («Внешние ссылки»). Подозрительное Сообщение должно быть заранее подготовлено и не содержать работающих URL, телефонов, реквизитов либо кодов.

## Состояния макета чата Avito

### Обычная системная подсказка

Макет может показывать нейтральную сервисную реплику, например о доступности Avito Доставки. Она не является предупреждением, не передаёт данные в тренажёр и не открывает CTA. Этот случай нужен, чтобы на демо была видна разница между обычной помощью в сделке и реакцией на риск.

### Подозрительное Сообщение

После подготовленной реплики собеседника макет вызывает демонстрационный анализ. До завершения анализа допустимо показать короткое состояние обработки, но не блокировать чат и не выдавать тревожное сообщение до результата.

Для MVP анализ может быть детерминированным по подготовленному набору признаков. В презентации его следует называть прототипом AI-модерации Avito, а не утверждать, что одного ключевого слова достаточно для достоверного вывода.

### Предупреждение

При высоком риске показать отдельную сервисную реплику в ленте чата, визуально отличённую от Сообщений покупателя и продавца. В ней должны быть:

- спокойное предупреждение, что действие или переписка могут быть небезопасными;
- конкретный понятный признак: например, внешняя ссылка для оформления;
- основное действие «Разобрать ситуацию»;
- вторичное действие «Продолжить чат» или закрытие подсказки.

Не называть собеседника мошенником как установленный факт, не показывать внутреннюю уверенность модели и не запрещать пользователю продолжать переписку.

### Согласие

Нажатие CTA открывает компактный экран или модальное окно перед переходом. Пользователь должен видеть, что в тренажёр уйдёт только обезличенный Снимок диалога, и иметь две возможности: подтвердить передачу или отменить её. При отмене пользователь остаётся в макете чата, а контекст не отправляется.

### Рекомендация тренажёра

После успеха фронтенд открывает промежуточный экран тренажёра. Он показывает:

- название подобранной Темы;
- краткое объяснение связи с ситуацией без раскрытия внутреннего промпта либо rubric;
- рекомендуемое первое действие: Теория, Quiz или открытый Уровень;
- кнопку начала рекомендованного действия;
- ссылку к общему каталогу Тем.

Далее используется существующая навигация тренажёра. Frontend не вычисляет открытость Уровня: он запрашивает её у backend и, если практика ещё закрыта, ведёт в Теорию выбранной Темы.

## Граница данных и будущий API

Единственный новый внешний сценарий — запрос на получение персональной рекомендации из чата. Имя маршрута, точные DTO и статусы утверждаются вместе с OpenAPI при реализации; ниже — обязательная семантика.

### Вход

Фронтенд передаёт только после согласия Пользователя:

- роль Пользователя в сделке: `buyer` или `seller`;
- обезличенный Снимок диалога из 2–6 Сообщений с ролью автора и текстом;
- риск, который заметила модерация: `phishing`, `prepayment`, `delivery`, `external_messenger`, `account_takeover`, `fake_payment` либо `social_engineering`;
- ограниченный список нормализованных признаков риска, максимум три;
- демонстрационный источник `avito_chat_demo`.

Не передавать в URL, local storage, логи UI или request body реальные идентификаторы чата, аккаунта, объявления, контакты, ссылки, реквизиты, коды, полную историю либо сырые внутренние оценки модели. В демонстрационных данных эти значения не должны присутствовать вовсе.

### Выход

Backend возвращает подобранную опубликованную Тему текущей Ролевой ветки, причину рекомендации в безопасной для показа форме и серверное рекомендованное действие. Ответ также должен содержать устойчивый путь/параметры для перехода к Теории либо выбранному Уровню.

Подбор ограничивается существующими Темами и Сценариями. AI может классифицировать контекст и объяснять соответствие, но не создаёт новые Сценарии, не начисляет Баллы и не управляет Прогрессом.

### Ошибки

- При отмене согласия сетевой запрос отсутствует.
- При `401` показать вход в тренажёр и сохранить только локальное намерение продолжить демо, но не сам Снимок диалога.
- При временной ошибке показать retry и безопасную альтернативу: каталог Тем или общую Тему безопасности; не придумывать рекомендацию на клиенте.
- При нераспознанном или неподдержанном риске показать общую рекомендацию по безопасной сделке, возвращённую сервером.

## Ответственность frontend

- Макет чата воспроизводит заранее определённые Сообщения и событие AI-модерации; он не подключается к реальному Avito API.
- Нативное предупреждение находится в ленте чата как сервисная реплика, а не как сторонний рекламный баннер.
- Согласие Пользователя — обязательное условие вызова integration API.
- Типы запросов и ответов валидируются на API boundary так же, как существующие сущности фронтенда.
- Переход в тренажёр использует ответ backend, а не сопоставление темы по ключевым словам на клиенте.
- Существующие экраны Тем, Теории, Уровней, Прохождений и Result не меняют свои правила прогрессии.

## Проверяемый демо-сценарий

1. Открыть макет чата в роли покупателя.
2. Показать обычную системную подсказку об Avito Доставке.
3. Показать Сообщение с подготовленной внешней ссылкой и срочностью.
4. Убедиться, что в чате появляется сервисное предупреждение и CTA.
5. Нажать «Разобрать ситуацию», подтвердить передачу обезличенного Снимка диалога.
6. Увидеть рекомендацию Темы «Фишинговые ссылки» и перейти в её Теорию или доступный Уровень.
7. Вернуться к каталогу Тем либо начать Прохождение.

Также вручную проверить отмену согласия, отсутствие предупреждения в нейтральном сценарии, ошибку рекомендации и переход для роли продавца.

## Вне рамок демо

- доступ к настоящим чатам, аккаунтам или API Avito;
- фоновый мониторинг переписки тренажёром;
- хранение реальной истории чата;
- автоматическая блокировка сделки или собеседника;
- генерация нового Сценария вместо подбора курируемой Темы;
- модельный скоринг, обучение модели и метрики качества production-модерации.
