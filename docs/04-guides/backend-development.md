# Развитие бэкенда

Этот документ описывает правила для текущей структуры проекта. Он не закрепляет детали функций, которые команда ещё не согласовала.

## Куда помещать код

| Задача | Пакет |
| --- | --- |
| JSON, параметры URL, HTTP-статусы | HTTP-обработчик |
| Правила прохождения, переход между шагами, начисление результата | `services` |
| Чтение и изменение PostgreSQL | `repositories` |
| Структуры хранения и JSON-представление | `models` или отдельные DTO при расхождении контрактов |
| Создание инфраструктуры и связывание зависимостей | `app_builder` |
| Работа с локальной моделью | отдельный пакет AI-провайдера, вызываемый сервисом |

Сервис не должен читать переменные окружения, создавать подключение к БД или знать URL Ollama. Эти зависимости собираются на старте приложения.

## Порядок добавления функции

1. Уточнить пользовательский поток и состояния, которые действительно нужны.
2. Зафиксировать HTTP-контракт до реализации обработчика.
3. Если меняется хранение, создать обратимую миграцию `.up.sql` и `.down.sql`.
4. Добавить репозиторный метод.
5. Реализовать бизнес-правило в сервисе.
6. Подключить обработчик и зависимость в composition root.
7. Добавить тесты сервиса и интеграционную проверку репозитория или HTTP-контракта.
8. Обновить соответствующий раздел документации.

## Ошибки и HTTP-ответы

Сейчас обработчики часто возвращают текст исходной ошибки, а ошибки репозитория напрямую превращаются в `404` или `500`. При развитии API нужно ввести ограниченный набор прикладных ошибок и единый JSON-формат ответа. До согласования формата документация не предлагает вымышленную схему.

## Изменения, которым нужен ADR

ADR нужен, если команда:

- отказывается от монолита или меняет границы слоёв;
- меняет способ запуска генеративной модели;
- выбирает механизм, от которого зависят несколько модулей: очередь, кэш, событийную модель, отдельный сервис;
- закрепляет сложный способ хранения диалога, который трудно безопасно заменить.

Обычный endpoint, новое поле ответа или локальный рефакторинг отдельного модуля ADR не требуют.
